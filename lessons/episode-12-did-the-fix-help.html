Episode 12 — Did the Fix Help?

Episode 12 · Module 3 — Comparing Builds · Audio 7:00 · Statistics for Legal Evals

Audio

The legal department has rewritten the prompt for clause extraction on its contract intelligence platform — the tool that reviews commercial agreements against the company playbook — and run the same test set through the platform before and after the change. Same questions, new prompt. Better? This episode answers that with McNemar’s exact test and the paired bootstrap, the two tools for before/after comparisons on the same test set. It is the most common comparison in legal evals, and the easiest to get wrong by testing the new prompt on different questions.

The Premise: Same Questions, Before and After

Each test item is a clause-extraction task: the platform either extracts the clause correctly (a pass) or it does not (a fail). The old prompt and the new prompt each run on the same items, so each item produces a pair of outcomes. The four possible pairs are:

New prompt passes New prompt fails Row total
Old prompt passes a — both pass c — old passes, new fails a + c
Old prompt fails b — old fails, new passes d — both fail b + d
Column total a + b c + d a + b + c + d

The pairs where both prompts agree — a and d — say nothing about which prompt is better. Both passing means the item was easy for both; both failing means it was hard for both. The comparison turns on the discordant pairs: b, the items the fix repaired, and c, the items the fix broke. If the fix did nothing, b and c should be about equal: each discordant pair is equally likely to favour the old prompt or the new one. If b is much larger than c, that is evidence the fix helped. The whole test is a question about b and c alone.

That is the first clarification this episode makes, because it is the one most often missed: McNemar’s n is the number of discordant pairs, not the number of items. A test set of 200 items with 22 discordant pairs has n = 22 for this test, not n = 200. The other 178 items were run, and they matter for the pass rate, but they carry no information about which prompt is better.

McNemar’s Exact Test

The null hypothesis is that the two prompts are equally good, so each discordant pair is a fair coin flip: a 50% chance it favours the new prompt, 50% that it favours the old one. Conditional on the number of discordant pairs, n = b + c, the count b follows the binomial distribution with n trials and probability 0.5 (Episode 5). The two-sided p-value is twice the probability of seeing a split as lopsided as the one observed, or more so, in the direction observed:

p = 2 × P(X ≤ min(b, c))  where X ~ Binomial(n, 0.5)

It is called the exact test because the probability comes from the binomial distribution itself, not from a normal approximation to it. With 20 or so discordant pairs, the normal approximation is poor — the counts are small and discrete — so the exact calculation is the one to use. There is also an asymptotic version of McNemar’s test, based on a chi-squared statistic; it is not used in this episode, and the p-values below are all exact.

The Worked Examples: Four Splits, Four Answers

Four discordant splits, worked the same way. In each row, n is the discordant count, the smaller count is the tail that is summed, and the p-value is twice the one-sided binomial tail.

Split (b vs c) Discordant n One-sided tail Two-sided p Reading
14 vs 8 22 P(X ≤ 8) = 0.1431 0.29 Little evidence against the null
18 vs 4 22 P(X ≤ 4) = 0.0022 0.004 Strong evidence against the null
15 vs 5 20 P(X ≤ 5) = 0.0207 0.041 Evidence against the null, just inside 0.05
14 vs 6 20 P(X ≤ 6) = 0.0577 0.115 Not enough evidence against the null

The working for the first row: with n = 22 and a fair coin, P(X ≤ 8) is the sum of the binomial probabilities for 0 through 8 successes, each C(22, k) ÷ 222. That sum is 0.1431; doubling it for the two-sided test gives p = 0.286, shown as 0.29. The other rows follow the same arithmetic. The one-sided tail is doubled rather than taken as the answer because the test does not assume in advance which direction the fix went: a split of 8 vs 14 would be equally surprising.

The third and fourth rows are the boundary, and the boundary is the lesson. Fifteen against five gives p = 0.041, inside the conventional 0.05 threshold. Fourteen against six gives p = 0.115, outside it. One pair moving from one side to the other — a single item, re-graded or re-run — flips the conclusion. That is not a defect in the test. It is discreteness: with 20 discordant pairs, the p-value can only take a handful of values, and 0.05 falls between two of them. A report that says “significant” for 15 vs 5 and “not significant” for 14 vs 6, without showing the interval and the effect, is reporting the threshold, not the evidence. The difference between the two splits is one item; the difference between the two verdicts is a convention.

Language is qualified throughout: “evidence against the null”, not “real” versus “noise”. A p-value of 0.29 is not proof the fix did nothing; it is a statement that a split of 14 vs 8 is unsurprising if the prompts were equally good. A p-value of 0.004 is not proof the fix worked; it is a statement that a split of 18 vs 4 would be surprising if they were equal.

The Two Illustrations

The contract platform’s prompt fix. The clause-extraction prompt is rewritten, and both versions run on the same test set. The discordant split is 18 vs 4 — eighteen items the new prompt extracts correctly that the old one missed, four items it newly gets wrong — with p ≈ 0.004. That is evidence against the null, and the direction is clear: the fix repaired more than it broke. The department still checks the four newly broken items before shipping: if they share a clause type, the fix has a cost the headline hides (Episode 8), and the minimum important difference (Episode 10) still decides whether 14 net repairs are worth the re-validation.

The citation-check prompt fix. The legal research assistant — the tool that retrieves authorities and drafts answers with citations — gets a rewritten prompt for its citation check, the step that verifies each cited authority supports the proposition it is cited for. Before and after, on the same set of research questions, the split is 15 vs 5, p ≈ 0.041. That is evidence against the null, just inside the threshold, and the department treats it as a provisional result: the interval on the difference is wide, the split sits one item from the boundary, and the fix is re-tested on a fresh set of questions before it ships. The second illustration exists to show the same test on a different tool: the statistics do not change when the workflow does.

Why Pairing Buys Power

Running both prompts on the same items is more powerful than running each on its own set of items, and the reason is the agreement between the pairs. An unpaired comparison must allow for the possibility that the two groups of items differ in difficulty. A paired comparison does not: the same item is judged twice, so item difficulty cancels out, and only the disagreements remain.

A worked comparison, with the assumptions stated: 100 items, the old prompt passes 70, the new prompt passes 76, and the discordant split is 14 vs 8 (so a = 62 items both pass, d = 16 both fail). The paired standard error of the difference is √(0.22 ÷ 100) = √0.0022 = 0.047, or 4.7 points. The unpaired standard error, treating the two pass rates as independent samples of 100, is √(0.70 × 0.30 ÷ 100 + 0.76 × 0.24 ÷ 100) = √(0.0021 + 0.0018) = √0.0039 = 0.063, or 6.3 points. The paired interval is narrower, because the paired calculation uses only the discordant rate (22%) while the unpaired calculation carries the full variance of both rates.

The gain depends on the correlation between the paired measurements — how much the two prompts agree. When the prompts agree on most items, the discordant rate is low and the paired standard error is small. When they disagree on nearly everything, the gain shrinks. There is no universal multiplier: an earlier draft of this series claimed pairing quadruples the power, and that claim was withdrawn, because no single number describes the gain. The gain is whatever the discordant rate and the correlation make it, on that test set.

The Paired Bootstrap, and When It Disagrees with the Exact Test

The paired bootstrap is the interval to report alongside McNemar’s p-value. It resamples the paired items with replacement — whole pairs, never one side of a pair alone — computes the difference in pass rates for each resample, and takes the middle 95% of those differences as the interval. It answers a different question from the exact test in form, but the same question in substance: how large is the difference, and how precisely is it measured?

Sometimes the two disagree, and the disagreement is the most instructive part of this episode. Take a small test set of 10 items: the new prompt repairs 4 items, breaks none, and the other 6 are unchanged. The discordant count is 4, all in one direction, and the exact McNemar p-value is 2 × (1/2)4 = 2 ÷ 16 = 0.125. The difference in pass rates is 4 ÷ 10 = 0.40. A normal-approximation interval on that difference runs from about 0.08 to 0.72 — working: the differences per item are four +1s and six 0s, mean 0.40, sample standard deviation 0.516, standard error 0.516 ÷ √10 = 0.163, and 0.40 ± 1.96 × 0.163 = 0.40 ± 0.32. A percentile bootstrap interval on the same data can also exclude zero. So the interval says “the difference is away from zero” while the exact test says p = 0.125.

Do not explain that away as “different questions” — the two can address the same underlying performance difference. Check four things instead:

  • Discreteness. With 4 discordant pairs, the two-sided exact p-value can only take three values: 1.000 for a 2 vs 2 split, 0.625 for 3 vs 1, and 0.125 for 4 vs 0. No split of 4 pairs can produce a p-value below 0.05. The test cannot return a significant result at this size, however lopsided the split.
  • Small-sample behaviour. Ten items is a small test set. The bootstrap resamples 10 items, so its intervals are built from very little information, and percentile intervals at n = 10 are known to be optimistic.
  • Interval construction. A normal-approximation interval and a percentile bootstrap interval are built differently from an exact binomial tail. They make different approximations, and at small n the approximations diverge. A bias-corrected bootstrap interval, or an exact interval on the difference, would be wider.
  • Assumptions. The exact test conditions on the discordant count; the bootstrap does not. The two are answering the same question under different conditionings, and at small n the conditioning matters.

Do not teach automatic deference to one method. Report both, state which assumption each one rests on, and say what would settle the disagreement: more discordant pairs. With 4 discordant pairs the question cannot be settled; with 22, it can.

Checklist: Before/After on the Same Test Set

  • Run both versions on the same items. Different questions throw away the pairing, and the pairing is the best evidence you have.
  • Build the 2 × 2 table. Report b and c, not just the two pass rates.
  • Use the exact test at small discordant counts. Report the discordant n beside the p-value.
  • Report the paired bootstrap interval beside the p-value, and the net difference (b − c) in points.
  • If the exact test and the bootstrap disagree, check discreteness, small-sample behaviour, interval construction, and assumptions — and collect more discordant pairs.
  • Read the newly broken items (c) item by item before shipping, whatever the p-value says.

The Use Case

Before/after on the same test set is the most common comparison in legal evals: a prompt fix on the contract platform, a citation-check fix on the research assistant, a retrieval change on the RAG tool, a new model version behind the same interface. The design is always the same — same questions, paired test — and the failure mode is always the same too: testing the new version on fresh questions and comparing its score with the old version’s score on the old questions, which confounds the fix with the difficulty of the questions. Same questions, paired test. Different questions, and the best evidence is gone.

Conclusion

Same questions, paired test. Different questions, you have thrown away your best evidence. McNemar’s exact test asks whether the discordant pairs split evenly, and its n is the discordant count, not the item count. The paired bootstrap puts an interval on the difference. When they disagree at small n, the disagreement is information about discreteness and interval construction, not a reason to defer to one method automatically. And a p-value of 0.041 against 0.115 is one item apart — report the split, the interval, and the broken items, and let the reader see the evidence instead of the verdict.
